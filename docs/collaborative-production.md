# Collaborative Gutenberg Production — development branch

> **Current (2026-11-24):** Adaptive Surgery v2 supersedes the fixed repair/review limits, style-only surgery constraints, viewport defaults and stagnant-target halt rules described in earlier historical sections below. See [Master Plan & Progress Tracker](master-plan.md), especially §4, and the current addendum at the end of this document. Earlier contracts remain for traceability; **do not implement the obsolete limits as active behavior**.

This specification applies only when **Native Gutenberg** is selected. HTML/CSS production retains its four-agent stream and explicit manual conversion. No automatic publishing or paid retries occur.

The v0.12 native path carries an application-bound production specification throughout the existing handoffs. [Current responsibilities and contract](production-team-upgrade.md)

## Contract

1. Boss defines criteria. Designer produces the scoped HTML/CSS visual reference, renders it in Playwright, and submits real desktop/mobile evidence to Boss. Boss explicitly approves or requests a targeted design correction (at most two review rounds). Developer cannot start before approval.
2. Approved HTML reference is the *visual target*, **not** the Gutenberg deliverable. Its identity is passed via SHA-256 and compact approval/handoff metadata; full reference is supplied only where actually required for implementation.
3. Developer emits one full constrained version-1 native block plan with stable component IDs. The plan is persisted as a private, 24-hour working draft. Compiler recovery modifies the draft via bounded style-only field patches, not full JSON regeneration. The deterministic PHP compiler produces core blocks; arbitrary CSS/HTML is rejected.
4. A network-isolated Playwright renderer inspects HTML reference and native preview independently at 1440, 768 and 390 CSS px. JS is disabled for inspection, external requests blocked. Screenshots, element geometry, computed CSS, horizontal overflow, accessible-name indicators and automated WCAG axe-core findings become QA evidence.
5. The same isolated service calculates screenshot pixel difference using previously collected JPEGs. This is a coarse visual-difference metric (lossy JPEG, sampled pixels), **not** a pixel-perfect equivalence assertion. DOM/typography comparison maps matched text nodes back to plan IDs.
6. The Validator receives measured evidence and four genuine desktop/mobile screenshots as Anthropic image messages. It records findings by component ID and must identify unverified issues.
7. The orchestrator chooses only pending impacted components. Boss makes a scoped delegation decision and can request a narrowly focused Designer correction before Developer changes a component. A revision modifies a single existing node with the same ID and type. The original HTML reference, unaffected siblings and their findings are preserved. Per-component fingerprints distinguish direct edits from ancestor changes; descendant findings are invalidated while unrelated sibling evidence is reused. Every candidate is compiled and rendered again at all widths; a scoped vision review covers the modified component; the deterministic findings and visual score determine whether a candidate is retained. We preserve the best-scoring artifact.
8. Cost admission is deterministic and based on configured per-million input/output token prices. Each request pre-reserves expected input/maximum output and image overhead; before revision, conservative projected spending must remain under **80%** of max-job USD. This reserve does not promise exact provider billing: caching and image token usage may vary. At most three revisions are attempted. Failed or over-budget repairs do not trigger unrestricted retries.
9. The terminal artifact, explicit stopping reason, impact/reuse metadata and issue/revision history are archived. Pending findings => **Uncompleted** and best artifact remains exportable. No outstanding findings => **Needs review** until the WordPress block editor parser and registered block validation verify the exact generated block content. Only eligible records with verified evidence become **Completed**. Browser output preview is never evidence of a full WordPress editor round-trip.

## Data and evidence

- `artifact`: `schemaVersion`, `content`, `preview`, `contentSha256`, `checks`, `blockCount`
- `referenceHtml`: immutable HTML design target
- `quality.issues`: structured outstanding findings with stable component owner IDs
- `quality.revisions`: attempted changes, previous/new issue counts, accepted/rejected decision, evidence hashes
- `quality.evidence`: three-width DOM snapshots and hashes, bounded base64 desktop/mobile screenshots, separately for reference and best native artifact
- `quality.pixelComparison`: per-width sampled image differences
- `usage`, `agentMetrics`, `estimatedCostUsd`, `budgetUsd`: estimates and per-request usage

Archived jobs are private to administrators; image evidence is not served by an unauthenticated route. The browser renderer has its own Docker network. Explicit draft/pattern save is unchanged; output status alone never publishes a page.

## Deployment and acceptance

Use `compose.yaml` with `SYNDAMORPH_RENDERER_URL=http://renderer:3000/render` for the private WordPress-to-renderer link. The native collaborative branch requires the same renderer service to handle `/inspect` and `/compare`; if unavailable it must not report QA success.

- Run `php tests/real-ai-poc-test.php` and `node --check` on changed JS, plus `php -l` on PHP.
- Build the renderer Docker image; run `node --test renderer/inspect.test.js` against port 3999 in CI to exercise real Chromium, axe-core, pixel comparisons and the legacy /render endpoint.
- Test HTML-only production with existing four-call mock regression; verify source import / conversion never changes.
- Test Gutenberg mode in a disposable WordPress environment: verify real HTML and native block output; inspect browser QA and revisions; check spending thresholds and History, use Save & Open Editor and ensure no Gutenberg invalid-block recovery warnings.
- Never spend actual model tokens without authorized API settings. Automated CI mocks provider calls; live visual fidelity and WordPress Gutenberg browser acceptance remain separate checks.

## Job memory and context optimization (v1.3)

Job-local memory stores candidate fingerprints, rejected patches, per-target feedback and stalled-target counters. Equivalent plans skip browser and model QA. Three unsuccessful attempts on one target cause the scheduler to try other eligible targets; the job stops when no targets remain, the 80% estimated budget threshold is reached, or the runtime guard is reached. The private archive retains the memory snapshot. Initial QA sees full images; scoped revisions use text-matched screenshot crops with a full-image fallback. Compact measurements omit unrelated elements and screenshot bytes. Host-level accessibility rules are excluded from section repairs. Shared static standards use an Anthropic ephemeral cache breakpoint; actual cache hits depend on provider model and minimum prefix length. Cost estimates include cache reads at 0.1x and five-minute cache writes at 1.25x base input price. Live token savings require measurement; CI uses mocked model calls. Rebuild renderer after updating this branch.

## Native serialization and recovery (R47–R52)

The dashboard initializes the actual core block registry before validating native content. Layout blockGap is stored in block attributes; preview-only CSS lives outside serialized block markup. Failed validation exposes Retry Validation and Recompile archived artifact (no AI). Recovery preserves historical events, uses the latest archived best plan, checks the prior SHA-256, runs browser inspection again, and cannot inherit stale vision approval. Registered-block validation of recovered artifacts is recorded independently of production completion. Cross-job engineering observations are keyed by failure type, core block, WordPress version and compiler hash, deduplicated by job/artifact, bounded, and marked corrected only when a changed artifact passes registered validation. These observations are not agent prompt instructions; broader adaptive learning is a separate milestone. The CI-only browser fixture runs on disposable WordPress and checks actual block validation plus rejection of the original inline-gap defect. No model calls or releases are involved.

## Core support serialization audit (R53–R55)

Custom button typography emits the Gutenberg-specific `has-custom-font-size` support class on the anchor (not the wrapper). The real WordPress CI matrix covers all seven supported block types, plain and styled content, heading levels, text alignment, container justification, gradients, fluid typography, spacing and the GEN9 custom-font CTA regression. The original GEN10 gap regression remains mandatory. Existing archived plans can be recompiled without provider calls; successful editor validation does not imply renewed visual approval.

## Adaptive Learning Engine (R39–R46)

Persistent learning records are stored in the local WordPress option `syndamorph_learning_v1`, independently of job-local `SyndaMorph_Job_Memory`. Categories: agent, engineering, capability. Classification accepts only allowlisted compiler diagnostics, validated native style keys, and explicit capability preflight notes. No raw prompts, personal copy, HTML, screenshots, credentials or full model transcripts enter the store. Schema lessons require successful recompilation; targeted repair lessons require actual browser and scoped QA acceptance with reduced issue score. A model's assertion alone is never sufficient. Identical evidence is deduplicated; limits are 150 rules, 40 evidence IDs per rule, 3 recalled rules by default.

Developer generation can receive verified preventive rules. Schema repair matches the failing block and diagnostic signature, while visual repair matches issue category, layout, component relationship, and authorized operation. Engineering and capability observations stay out of agent instructions. Compiler source checksums exclude stale lessons. The History Learning panel supports review, enable, disable, delete, and explicit bootstrap. Bootstrap reads bounded structured events and reindexes only verified compiler receipts from the current revision. Each receipt identifies a compiled artifact, repair route, and scoped diagnostic or compiler fact. Reindexing the same job and attempt is idempotent.

R39–R46 are learning infrastructure, *not* self-modifying code. Compiler Self-Healing (R56–R63) remains a separate future phase. Existing native compilation, HTML production, source import, cost gates and WordPress save semantics remain unchanged.


## Controlled collaboration + surgical recovery pilot (November 24, 2026)

**Scope:** Experimental native Gutenberg pipeline on `feat/secure-gateway-leasing-v1`. HTML-only mode, published `main/v0.11.1`, production plugin release, and WordPress editor serialization rules are not changed.

**Compact assignments:** Boss must return a bounded JSON work order with title, sections, constraints and acceptance criteria. Raw prose is not forwarded as the next agent's instruction. Review handoffs use explicit decisions, issue targets and artifact checksums; only an agent doing implementation receives the full HTML reference.

**Visual approval:** The Designer now owns the HTML/CSS reference instead of the Developer. The same isolated Playwright inspection is called for Designer evidence, native Developer output, and independent Boss comparisons. The Boss receives bounded geometry, screenshots and a reference checksum, not the full generated HTML in the review message. An explicit `decision: approved` is mandatory. A rejection produces a compact revision request; the Designer gets one chance to revise before the design stage fails safely. The Developer receives only a Boss-approved reference.

**Internal shared tool registry:** `production-tools.php` grants Playwright inspect/compare/crop to Boss, Designer, Developer and Validator, while compilation and native plan patches remain Developer-only. Tools are called through the PHP orchestrator; this is not yet autonomous Anthropic tool-use/model-issued calls. New roles must be explicitly granted permissions.

**Schema surgery:** Developer makes one full native-plan generation. The working plan is stored in an expiring private WordPress transient identified by a random key, plus a checksum and revision number. The compiler supplies a concrete field path. The surgery service extracts the smallest matching node, attempts only lossless deterministic corrections, then requests up to eight bounded field-level attempts from Developer if necessary. Model responses use `{id,changes:[{path,value} | {path,op:"remove"}]}`, never an entire plan. The field allowlist permits native styles only; content, IDs, block types and siblings cannot be edited through this route. An advancing correction can be retained while additional defects remain; a patch that fails on its original field is rejected. Full-plan compiler validation remains mandatory before marking lessons verified. Budget admission still enforces the existing 80% repair limit and 16,384-token reservation. If a job cannot compile, the error includes the private draft key and surgical metrics; there is not yet an editor-facing resume action.

**Final Boss authority:** Browser-based native QA also requires an explicit Boss `decision: approved` or actionable `changes_requested` response. No model approval overrides deterministic accessibility/overflow findings. An unresolved Boss review remains Uncompleted, while even Boss-approved artifacts still require the real WordPress editor validation before Completed status.

**QA surgical repair (GEN-013 follow-up):** Browser QA now requests at most three field-level changes per Developer response using the same native `{id,changes}` contract as compilation. A change may identify an existing descendant via `target` when its ancestor owns the reported issue (e.g. paragraph bottom margin affecting parent stack spacing); it cannot escape the assigned subtree. The Developer receives a bounded list of local node styles, issue evidence, crop screenshots and compact failed-attempt feedback, **not a full component replacement**. Existing deterministic repairs are translated into equivalent property deltas. Every candidate is compiled and browser-reviewed at all three widths; accepted candidates alone update the 24-hour persistent plan. Rejected candidates are rolled back and fingerprinted, and their precise changed fields are available as feedback. Unchanged sibling identity/attributes remain protected.

**Visual issue reconciliation:** Source-impact hashing still identifies which component actually changed, but QA `reviewScope` now includes visual-layout ancestors. This allows a correction to `sm-hero-intro` to resolve Boss's issue against `sm-hero-stack` without falsely marking siblings as modified. Previous model findings in that review scope are replaced with the new scoped Boss report, while globally recomputed deterministic violations are always authoritative. New model findings, including new sibling regressions, cannot be silently discarded. Acceptance requires reduced issue score (or identical score with pixel improvement), no *new* issues, and no material overall pixel-regression (0.01 tolerance). Model approval alone never guarantees acceptance.

**Escalation:** After three failed attempts against the same target, no editable targets, or global stagnation, the team stops retrying. When allowed by the 80% budget gate, it asks Boss once for a compact `engineering_blocked | design_review_required | manual_review_required` classification and a concrete next action. This is advisory; it never changes the previously approved reference or publishes a failed candidate. The archived result includes phase-specific `stageStatus`, blocker IDs and an escalation reason. The UI renders the actual QA blocker rather than a generic Uncompleted label.

**Verification:** Added a GEN-013 regression case where an ancestor-owned spacing issue is corrected via a descendant-only margin patch and the final Boss verdict clears it in one round. Separate tests verify rejected sibling edits, persisted QA revisions, bounded field-level replies, and a stalled-repair escalation. The benchmark is mocked and still requires comparative live runs and Gutenberg editor testing before global promotion.

**Learning** A compilation failure produces an observed rule when the compiler diagnostic matches known vocabulary. Only full compilation and identity validation can emit a verified receipt for an accepted schema correction. Compiler-validated facts such as empty painted Groups can also emit a receipt. Compiler revision hashes invalidate stale lessons. Schema recovery exposes only paths that can safely address the current diagnostic. Unsupported structural edits are reported with the original diagnostic and stop before a model retry.

**Evaluation metrics:** `surgery` reports the persistent draft key, deterministic corrections, paid patch calls, full-plan regenerations (expected zero), ordered patch outcomes and accepted QA revisions. Mock CI includes a GEN-012-like invalid background-to-gradient correction and asserts one targeted paid patch, unchanged content, separate original and corrected checkpoints and a verified lesson. This is a regression fixture, **not** a live cost, fidelity or production-readiness benchmark.

**Global promotion gate:** Do not make this the default method for all agents yet. Run equivalent jobs through the old and new flows, compare success rate, valid editor round-trips, accepted/rejected repair rates, total tokens/cost, elapsed time and unchanged approved sibling hashes. Promote only if repair safety and quality are at least as good and measured cost/latency justify it. Automatic Boss escalation of stalled QA is implemented as a terminal advisory; autonomous cross-agent delegation and design reapproval remain future milestones, not completed features.

## GEN-015 budget-governed continuation (November 24, 2026)

The experimental pipeline removes the fixed two-round design cap, eight-attempt schema cap, four-round QA stagnation cutoff, and per-component three-failure exclusion. **The 80% cost gate remains:** paid corrective work must fit inside 80% of the configured estimated job budget, preserving the remaining 20% for Boss escalation, issue summarization and final reporting. Initial work and final reporting remain subject to the full configured budget. Duplicate candidate detection, field-level patch restrictions, atomic rollback, compiler validity, safety checks and evidence-based approval remain mandatory. Failed/rejected candidates do not overwrite the last accepted draft.

This does **not** mean the web request can run indefinitely: the existing server/runtime safety limit and infrastructure timeouts are still present. A durable asynchronous resume mechanism is a separate requirement for genuinely budget-only termination across long-running jobs. The GEN-015 live trace ended with global_no_progress after four attempted QA repairs and about $0.021822 estimated cost against a $1 cap; this change addresses those arbitrary retry stops, not the underlying open visual discrepancies. Live retesting and full CI verification are required before claiming success.


## Adaptive Surgery v2 — current contract (2026-11-24)

**GEN-000025 progression:** The active QA loop promotes strictly lower comparable scores after independent regression checks. It uses the verified best candidate for repair, escalation and job control. A strategy can be reused with a different operation. [Current contract and regression evidence](adaptive-surgery-hardening.md#gen-000025-and-the-verified-best-candidate).

**November 25 hardening:** the active handoff, compiler transaction, capability matrix, inspection copy contract and metering changes are documented in [Adaptive Surgery hardening](adaptive-surgery-hardening.md). The statuses and benchmark below describe the original v2 checkpoint.

**Implementation status:** completed on `feat/secure-gateway-leasing-v1` at [`54a1833`](https://github.com/gnznovus/SyndaMorph/commit/54a1833354081a04421138b6e993b2c347ccdc1e). [MVP CI](https://github.com/gnznovus/SyndaMorph/actions/runs/45436215694) passed. This **supersedes** conflicting v1 contract statements above, without retroactively changing historical experiments.

1. **Design gate:** Boss explicitly resolves unsupported native requirements before approval. Old fixed two-round design limit is not active.
2. **Persistent base artifact:** Developer creates one complete plan, then repairs persisted nodes; repeated whole-plan generation for minor defects is discouraged.
3. **Coordinated atomic surgery:** An authorized repair can combine **up to eight changes** across scoped nodes, including **up to two scoped structural wraps**. All changes are compiled/validated together; preserve protected content, IDs, links and unrelated siblings. The earlier "style-only" assertion does **not** describe v2.
4. **Viewport evidence:** defaults are **375, 768 and 1440 px**, subject to supported explicit widths (not the old fixed 390px); track matched reference/native geometry, text and component bounds and candidate-induced defects.
5. **Acceptance:** retain safe verified improvement even if known pre-existing issues remain; reject genuine new regressions such as mobile overflow. Stable identity should not misclassify a pre-existing centering issue.
6. **Feedback:** keep proposed changes, rejected reasoning, measurements, residual issues and related ancestor/descendant attempt history; Boss prioritizes by severity/impact.
7. **Retries:** no arbitrary three-attempt/stagnation veto. A subsequent operation must have a distinct evidence-backed strategy and fit deterministic budget/authorization gates.
8. **Budget:** reserve **Developer + QA together** within the **80% corrective-work limit**; leave **20% for Boss escalation/reporting**. Count failed/review calls, images, token usage and relevant cache billing.
9. **Learning:** record matched/injected/followed/validated lesson outcomes. Do not claim live savings from scripted tests.
10. **Release gates:** backend and Gutenberg fixtures/Chromium repeatable tests passed; representative live-provider/WordPress execution **still requires acceptance**.

**Benchmark caveat:** replayed GEN-015 candidate could have improved weighted 38→34 but was rejected under old logic. Two **predefined-patch Chromium trials** under v2 scored hotel hero **26→18 (30.8%)**, gallery callout **20→0 (100%)**. Rubric/viewport changes prevent direct comparison to the earlier 38-point baseline. No production-wide live-provider savings have been established. See [master plan](master-plan.md) for evidence and future roadmap.
## Captured source scopes

Production Setup accepts a URL with **Native Gutenberg** output. Select **Section** to inspect the URL and choose one detected region. The manual viewport picker remains available for explicit variant matching. Select **Full Page** to use every discovered region in the captured page. URL discovery and desktop, tablet and mobile capture use the same allowlisted Playwright service as Source Inspection. A brief without a URL continues to use the original production path. HTML and ZIP imports keep their manual conversion paths.

Manual viewport selections must pass pinned copy and pixel comparisons before Developer handoff. The design approval contract, live evaluation and known gaps are documented in the [Bossy reliability audit](bossy-validation-audit.md).

Inspection pins the source URL, region identity, DOM selector, viewport-specific markup, text and resource inventory, screenshot and source order at 1440, 768 and 375 CSS pixels in administrator-only History. Exact source anchors are preferred when joining variants. Different trees can be aligned using unique content and landmarks. Ambiguous or device-only regions stay visible and block complete acceptance when their other required evidence is missing. Page screenshots and overlay-region screenshots retain the original overlay. Screenshots for unrelated regions temporarily suppress the captured overlay and its backdrop and record that isolation.

Each ready region starts its own existing Boss, Designer, Developer, native compiler, browser, Adaptive Surgery and editor workflow. The source comparison adds literal text, links, asset and function checks against what is actually visible at each width. For different source copy, the compiler can put native groups behind fixed desktop, compact, tablet or mobile visibility classes. Every group remains available in Gutenberg for editing. The SyndaMorph stylesheet applies the viewport rules on the front end.

Section uses the configured per-job cost ceiling. Full Page has a separately confirmed aggregate dollar budget and each of its regions continues to obey the per-job ceiling. Both preserve 80% for working calls and 20% for escalation. The provider allocation stays capped at 16,384 output tokens per scoped request; the page can use a larger number across independent calls. Raising a scope budget preserves prior spend. The manifest keeps all attempts, metered tokens and their reported cost. An unmetered request pauses further spend. A failed Section can pin corrected evidence while retaining its previous checkpoint. Paid retries require separate confirmation. A browser checkpoint can be inspected again without invoking a model, and recovery evidence does not itself approve a production gate.

Gutenberg verifies each archived artifact before SyndaMorph creates an **unsynced** pattern. A Full Page request copies only the verified native blocks into a single draft in original source order. The manifest records pattern IDs, page placement and content hashes. It can rebuild the same draft after more regions pass. It reports an edited draft or changed pattern before replacing the recorded content. The source scope can be reopened from History after a reload.

Page acceptance also requires all regions, matching viewport order, Gutenberg serialization of the combined block content, and real Chromium comparison of the reconstructed WordPress document at all three widths. Comparison checks both the first 900 CSS pixels and a scaled image of the complete page. Source comparisons retain the existing maximum 1.5% difference for any view and 0.5% average across views. Full-extent evidence also checks for a height delta within 10% or 16 CSS pixels, whichever is larger. Existing Designer-reference, accessibility and repair gates still apply. A reconstructed draft uses a content canvas to avoid duplicating captured site header and footer. It remains a draft after validation.

The AI compiler currently supports text and native layout groups. Source image and media conversion, custom booking, overlay, carousel or subscription behavior, and links whose destinations cannot be reconstructed are recorded as region blockers before a section spends money. A page with blocked regions can retain a partial draft and completed patterns. Its History status remains uncompleted.

`POST /syndamorph/v1/production-scope` pins discovery. The scope resource handles configuration, a single region attempt at a time, pattern saving, assembly and page validation. Region jobs remain normal private `GEN` History records. The parent `REF` checkpoint can be reopened in Production Setup. The MVP CI workflow runs `tests/production-scope-browser.cjs` with deterministic model responses, the real compiler, WordPress and Chromium.
