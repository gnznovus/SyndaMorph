## GEN-000026 compiler recovery and verified learning

GEN-000026 reached design approval and failed before native browser QA. Its original plan represented a decorative panel as a nested Group with a native gradient and minimum height, with no children. The compiler rejected that field as Invalid children. The schema handoff gave a generic children diagnostic alongside a style-only repair contract. Three paid retries proposed inserting a paragraph. Each proposal exceeded the actual edit authority. Seven archived calls used an estimated USD 0.008071 in total, including USD 0.002407 for the three schema retries.

The native compiler accepts an empty inner Group when it has a native minimum height and background or gradient. It serializes the existing Group without adding text, links, CSS, or placeholder blocks. Content Groups, Columns, Column, and Buttons still require their declared children, and arbitrary structural edits remain outside schema repair. Compiler recovery also moves an equivalent supported two-color gradient from background to gradient and retains the existing deterministic alignment and vertical margin corrections.

Schema repair now sends the exact compiler diagnostic and the permissible paths for that node. A children or other structural error outside the repair contract stops with its original diagnostic and expectation before requesting a style edit. Rejected operations record their actual validation failure and canonical signature. The existing budget and scoped retry limits remain in effect.

Completed compiler validation emits receipts with block scope, compiler revision, artifact hash, and repair route. Verified rules persist across jobs. Developer generation can retrieve bounded preventive rules; schema repair retrieves rules for the current block and normalized diagnostic. Observations, rejected corrections, and historical intermediate events lack that verification. Reindexing consumes verified receipts from the active compiler. Measured visual lessons keep separate layout and component relationships, and hybrid lessons require structural authority.

The native design contract now states the default Columns breakpoint. The historical archive retains its original status, and its visual fidelity remains open.

GEN-000019 and GEN-000023 also compiled using two deterministic normalizations each with protected copy. GEN-000020 and GEN-000021 compiled on replay. These replays used zero provider calls. ### Native capability contract

| Capability | Boundary and validation |
| --- | --- |
| CTA width | `button.style.width: "100%"` is available when active core registers the button dimensions width support. This is fixed at every viewport and fills a correctly sized Buttons container. Preview and the WordPress front end use the same width behavior in the browser fixture. A desktop intrinsic CTA that becomes full width only on mobile remains outside this native contract. Route an unresolved breakpoint requirement to Boss. |
| Typography casing | `style.textTransform` maps to core typography for headings, paragraphs and buttons. The native label preserves its literal casing. Supported values are `none`, `uppercase`, `lowercase` and `capitalize`. |
| Fluid gap | WordPress 7.1.2 discards `clamp()` for layout block gap. A supported simple length can depend on theme block-gap settings. Legacy plans stay readable and produce layout notes. New unsupported gap surgery is rejected before rendering. Responsive child spacing is available where its semantic effect fits. |
| Vertical alignment and constrained width | Core flex and constrained layouts require different groups. An outer vertical flex group can retain minimum height and center a nested constrained group. The width applies to children of that constrained group. Theme-owned padding and other defaults can still affect front-end geometry. |
| Responsive spacing and lengths | Fluid native padding and margins support the bounded length grammar, including one spaced addition or subtraction in the middle of `clamp()`. Group, Columns and Buttons margin support top and bottom. Per-breakpoint style objects remain outside the contract. |
| Native nesting | Structural surgery wraps ordered, consecutive authorized direct children of an existing Group or Column into a new Group. It can combine up to two wraps and up to eight operations total with styles. The compiler validates native block relationships, block limits, identities and serialized output. Custom HTML and arbitrary CSS remain outside the plan schema. |

Core references for these mappings. [Block Supports](https://developer.wordpress.org/block-editor/reference-guides/block-api/block-supports/), [Button metadata](https://github.com/WordPress/gutenberg/blob/trunk/packages/block-library/src/button/block.json), [Core layout implementation](https://github.com/WordPress/gutenberg/blob/trunk/lib/block-supports/layout.php)

## Evidence-based text antialiasing

Developer surgery can set `style.fontSmoothing` to `grayscale` on a Paragraph or Heading when replay isolates a source text rasterization mismatch. The compiler serializes a class that works with the existing `pretty` wrapping class. The class applies a neutral brightness filter to request grayscale compositing in Chromium and preserves literal copy, layout, and installed font selection. The existing visual and editor gates evaluate the resulting artifact.

The BKKGO intro replay measured a decrease from 1.231% to 0% on the exact Gutenberg-saved desktop section. See the recorded source and artifact hashes in the [BKKGO checkpoint](production-pilot-bkkgo.md#native-intro-paragraph-repair-v01246).

## Authored heading breaks and fixed native Grid

Use `preserveLineBreaks:true` on a Heading only when the approved source contains an explicit break. Provide two to six plain-text lines in `text`. The compiler escapes each line and inserts native rich-text breaks. Heading line heights from 0.90 to 0.99 support measured tight leading. The surgery content signature protects the break flag and the original text.

Use `gridColumns` from 2 to 4 on a Group when the source uses fixed equal tracks. The compiler emits core Group Grid layout and accepts one scoped dividing border on a Group. In compact BKKGO the equal Grid tracks preserve the two booking fields without the extra height introduced by the host Columns layout. Both captured compact widths passed after Gutenberg serialization. [BKKGO compiler and editor evidence](production-pilot-bkkgo.md#compact-hero-and-relocated-title-checkpoint-v01247)
